01 · Retrieval-Augmented Generation

The Multi-Stage RAG Pipeline

RAG decouples knowledge (indexed, versioned, auditable) from reasoning (the model). Quality is decided long before the prompt is built.

Ingestion→ Chunking→ Embedding→ Vector DB→ Retrieval + Rerank→ Grounded Generation
STAGE 1 · OFFLINE

Document Ingestion

  • Parse PDF/HTML/Markdown into a structure tree, not flat text.
  • Heading-aware chunking: ~400–600 tokens, 10–15% overlap, never split tables.
  • Attach lineage metadata: doc_id, version, effective dates, ACL tags.
  • Content-hash every chunk → idempotent re-indexing, cheap diffs.
STAGE 2 · ONLINE · ≤ 80 ms

Vector Search

  • Embed query with the same model + task type used at index time.
  • ANN via HNSW (m=16, ef_search=40–100) — tune recall vs. p99.
  • Hybrid: dense cosine + sparse BM25 / tsvector, merged with Reciprocal Rank Fusion.
  • Metadata pre-filters (tenant, status=active) inside the index query.
STAGE 3 · ONLINE · STREAMED

LLM Generation

  • Assemble context in relevance order, IDs inline: [pol_17_s4].
  • Schema-constrained decoding (JSON schema) → parseable, typed output.
  • Post-hoc citation verification: every claim must map to a retrieved chunk ID.
  • Abstain path when evidence is below threshold — never improvise.
RRF(d) = Σ 1 / (k + ranki(d)), k ≈ 60 — rank-based fusion avoids calibrating incompatible score scales between BM25 and cosine similarity.
02 · Retrieval Optimization

Why Vector Search Alone Isn't Enough

Bi-encoders compress an entire passage into one vector before seeing the query. That's fast — and lossy. Reranking restores precision where it matters.

BI-ENCODER · RECALL

Encode separately, compare cheaply

  • sim = cos(E(q), E(d))
  • Document vectors precomputed → O(log N) ANN lookup.
  • Misses negation, numeric constraints, and fine-grained term interplay.
  • Role: cast a wide net — Top-K = 50–100.
CROSS-ENCODER · PRECISION

Joint attention over (q, d)

  • score = f([CLS] q [SEP] d)
  • Full token-level cross attention — understands "fee not waived".
  • Cost: one forward pass per pair → only viable on a shortlist.
  • Role: re-score K candidates → Top-N = 3–8.
rerank.py — two-stage retrieval

candidates = await index.hybrid_search(query, top_k=50, filters=acl)

pairs  = [(query, c.text) for c in candidates]
scores = cross_encoder.predict(pairs, batch_size=32)   # ~25 ms on L4

ranked = sorted(zip(candidates, scores), key=lambda x: x[1], reverse=True)
context = [c for c, s in ranked if s >= MIN_RELEVANCE][:TOP_N]

if not context:
    return Abstain(reason="MISSING_EVIDENCE")       # never generate ungrounded
Corpus · 106–109 chunksHNSW + BM25 · ms-scale
Top-K = 50bi-encoder recall
Top-N = 5cross-encoder precision

Why Top-N wins

  • Lost-in-the-middle: models under-attend to mid-context passages; fewer, better chunks beat more.
  • Token economics: 50 → 5 chunks cuts prompt tokens ~90% and TTFT proportionally.
  • Hallucination: distractor passages are a leading cause of confidently-wrong citations.
03 · Technical Trade-offs

Fine-Tuning vs. RAG

Fine-tuning teaches behavior and form. RAG supplies facts and freshness. Most production systems need both — applied to different problems.

Dimension RAG Fine-Tuning (LoRA / full)
Knowledge update frequency minutesRe-index changed chunks; versioned, instantly reversible. days–weeksNew dataset → train → eval → deploy. Facts frozen at checkpoint.
Domain adaptability limitedCan't change tone, format, or reasoning style; bounded by base model. strongInternalizes jargon, output schemas, classification heads, task style.
Hallucination mitigation auditableCitations to source chunks; abstain when evidence is missing. opaqueKnowledge in weights — no provenance; can amplify confident errors.
Cost profile per-queryEmbedding + vector DB + larger prompts (context tokens dominate). up-frontGPU training + eval; cheaper per call with shorter prompts & smaller models.
Latency +50–300 msRetrieval + rerank hop; longer prefill from injected context. lowestSingle forward pass; a 1B LoRA classifier can serve in < 60 ms p95.
Pattern that works: fine-tune a small model for intent / routing / format, then use RAG for every factual claim the user can see.
04 · Real-Time AI

Streaming Tokens to Millions: WebSockets + Pub/Sub

Decouple connection state from compute. Gateways hold sockets; workers hold GPUs; the bus is the only thing that knows both.

ClientWSS, resumable session id, last-seen seq for replay on reconnect.
WS GatewayStateless pods, ~50–100k conns each; auth at upgrade, per-socket bounded queue.
Redis Streams / KafkaChannel per session; partition by session id for ordering.
LLM Worker PoolContinuous batching (vLLM/TGI); publishes token deltas with monotonic seq.
BACKPRESSURE · DEFENSE IN DEPTH
  • Per-socket high-water mark: bounded asyncio.Queue; slow clients get coalesced deltas, then disconnect — never unbounded buffering.
  • Token coalescing: flush every 30–50 ms or 16 tokens, cutting frames ~10× with no perceived lag.
  • Admission control: workers pull from a queue (credit-based) instead of being pushed to — GPU saturation surfaces as queue depth, not OOM.
  • Durability choice: Pub/Sub is fire-and-forget; Streams/Kafka + consumer groups give replay after gateway failover.
gateway.py — bounded fan-out with coalescing

async def pump(ws: WebSocket, q: asyncio.Queue[Delta]) -> None:
    buf: list[str] = []
    while True:
        try:
            d = await asyncio.wait_for(q.get(), timeout=0.04)
            buf.append(d.text)
            if len(buf) < 16 and not d.final:
                continue
        except TimeoutError:
            if not buf:
                continue
        await ws.send_json({"seq": d.seq, "delta": "".join(buf)})
        buf.clear()

def on_bus_message(q: asyncio.Queue[Delta], d: Delta) -> None:
    try:
        q.put_nowait(d)
    except asyncio.QueueFull:          # slow consumer
        metrics.slow_client.inc()
        raise SlowConsumer(d.session_id)   # close 1013, client resumes from seq
05 · Enterprise AI Security

Attack Vectors & Guardrails

An LLM app is an interpreter that executes untrusted natural language with access to private data. Treat every boundary accordingly.

PROMPT INJECTION
  • Direct ("ignore previous…") and indirect — instructions hidden in retrieved docs, emails, web pages.
  • Mitigate: input classifiers, delimited untrusted context, tool allow-lists, no auto-execution of side-effecting actions.
PII MASKING
  • Redact before logging, embedding, or sending to a third-party model.
  • Reversible tokenization (<CARD_4821>) keeps utility; vault re-hydrates only for authorized views.
RBAC FOR EMBEDDINGS
  • Vectors leak content — embedding inversion is real. Treat the index as the source data.
  • Enforce ACLs inside the ANN query (row-level security), not by filtering results afterwards.
RATE & COST GUARDRAILS
  • Token-bucket limits per user and per tenant, measured in tokens, not requests.
  • Hard caps on max_output_tokens, tool-call depth, and daily spend; circuit-break on anomaly.
retrieval.sql — ACL enforced at query time

-- Postgres RLS: the session can only ever see permitted rows
ALTER TABLE kb_chunks ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_acl ON kb_chunks
  USING (
    tenant_id = current_setting('app.tenant_id')::uuid
    AND acl_groups && string_to_array(
          current_setting('app.groups'), ',')
    AND status = 'active'
  );

-- ANN search inherits the policy automatically
SELECT chunk_id, text,
       1 - (embedding <=> $1) AS cosine
FROM   kb_chunks
ORDER  BY embedding <=> $1
LIMIT  50;
Post-filtering Top-K leaks via timing and empty-result side channels — and silently degrades recall.

Five principles to ship with

  • Retrieve wide, rerank narrow. Recall is cheap; precision is what the model sees.
  • Fine-tune for form, retrieve for facts. Small models route; grounded models answer.
  • Sockets ≠ compute. Scale gateways and GPUs independently through the bus.
  • Enforce security in the query, not the UI. RLS, redaction, and budgets live server-side.
  • Abstain beats improvise. Missing evidence is a valid, measurable outcome.
